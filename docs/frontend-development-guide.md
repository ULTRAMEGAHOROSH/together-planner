# Together Planner — руководство по разработке frontend

Версия 1.0 · 2026-11-17. Короткие правила на каждый день. Почему правила такие — `frontend-final-decisions.md` (`FD-xx`). Что делать — `frontend-final-roadmap.md`.

---

## 1. Как работать с задачами

1. Открыть roadmap §5 и взять **следующую задачу** (правило — §2).
2. Прочитать карточку задачи в roadmap §6 и решения FD, на которые она ссылается.
3. Отметить задачу «◐» в roadmap §5.
4. Сделать **только то, что в карточке**. Заметили что-то ещё — запишите в журнал roadmap §12 как отдельную задачу; в текущую не добавляйте.
5. Написать тесты из поля «Проверка» **в той же задаче**, а не «потом».
6. Пройти проверку §3 и общий DoD (roadmap, начало документа).
7. Отметить «☑», при отклонениях от плана — запись в журнал.
8. Один коммит на задачу (§10).

Если задача не помещается в одну сессию — разделите её на `XXX-NNa` / `XXX-NNb` в roadmap, каждая часть должна оставлять приложение рабочим.

## 2. Какая задача следующая

- Первая по порядку таблицы roadmap §5 задача со статусом ☐, у которой **P0** и все зависимости ☑.
- Пока не закончены все P0 (фазы 1–9) — P1 и P2 не берутся, даже если они в текущей фазе.
- После выпуска MVP: P1 по порядку таблицы, затем P2.
- ⛔ — не берётся, пока владелец продукта не ответил на вопрос OQ (decisions §14). Ответ записывается в decisions, статус меняется на ☐.

**Начать с FND-01** (обновить Node до 24 LTS: текущий 17.4 Angular 22 не поддерживает).

## 3. Команды и проверка после каждой задачи

### 3.1. Запуск

```bash
docker compose up -d postgres
```

```bash
cd backend && ./mvnw spring-boot:run
```

```bash
cd frontend && npm start
```

Для локального HTTP в `.env` должно быть `REFRESH_COOKIE_SECURE=false`, иначе браузер не сохранит refresh-cookie и после F5 сессия пропадёт. Frontend — `http://localhost:4200`, `/api` проксируется на `:8080`. Swagger — `http://localhost:8080/swagger-ui.html`.

### 3.2. Автоматические проверки

| Команда | Когда |
|---|---|
| `npm run lint` | каждая задача (после FND-08) |
| `npm test` | каждая задача |
| `npm run test:watch` | во время работы |
| `npm run build` | каждая задача |
| `npm run e2e` | после WEEK-08 — в задачах, которые трогают доску, расписание или сквозные сценарии; перед завершением фазы — всегда |

1. Регистрация нового пользователя → онбординг → пространство создано (после WS).
2. F5 — сессия на месте (после AUTH-05).
3. Неделя открывается, «‹ › Сегодня» работают (после WEEK-11).
4. Создать, изменить и удалить событие (после EVT-06).
5. Применить шаблон с предпросмотром (после TPL-07).
6. Ширина 375 px в DevTools — нет горизонтальной прокрутки.
7. В консоли нет ошибок.

## 4. Правила архитектуры

### 4.1. Слои (FD-10…13)

| Кто | Может импортировать | Не может |
|---|---|---|
| `core` | `@angular/*`, `rxjs`, `shared/time`, `shared/domain` | `features`, `layout`, `shared/ui`, `shared/timeline` |
| `shared` | `core/api/models`, другие части `shared` | `features`, `layout`, сервисы `core` с состоянием |
| `shared/timeline/engine` | `shared/time`, `shared/domain`, модели | **ничего из `@angular/*`** |
| `layout` | `core`, `shared`, `features/*/index.ts` | внутренние файлы фич |
| `features/x` | `core`, `shared`, `features/y/index.ts` (только разрешённые связи) | внутренние файлы другой фичи |

Разрешённые связи между фичами: `schedule → events`, `schedule → templates`, `calendar → events`, `layout → events`, `layout → onboarding` и `settings → onboarding` (карточка приглашения). Новую связь — сначала в decisions.

Границы проверяет ESLint (FND-08). Если правило мешает — это сигнал пересмотреть место файла, а не отключать правило.

### 4.2. Состояние (FD-25…28)

- Состояние — в `signal()` внутри стора; наружу — только `asReadonly()` и `computed()`.
- Стор экрана — в `providers` страницы. Root — только `SessionStore`, `ToastService`, `DataChanges`, `ViewContext`.
- HTTP и отмена — RxJS (`switchMap`, `takeUntilDestroyed`); в шаблоны попадают только сигналы.
- После мутации — `DataChanges.eventsChanged()` / `templatesChanged()`, стор сам перезагружает данные. **Не правим локальные массивы «на глаз»** и не делаем optimistic update: backend решает, что получилось (нормализация DST, версии).
- Нет NgRx, нет `BehaviorSubject` как хранилища состояния, нет глобальных «кэшей всего».

### 4.3. Время (FD-30…34)

- Локальная дата-время — строка `'YYYY-MM-DDTHH:mm'` или целые **локальные минуты** (`toLocalMinutes`).
- `new Date('…')`, `Date.parse`, `getHours()`, `getDate()` для локального времени — **запрещены** (ESLint). Исключение — `shared/time/**` и `core/time/**`.
- «Сейчас» и «сегодня» — только через `ZoneClock` в поясе **пространства**, а не браузера.
- Интервалы — полуоткрытые `[start; end)`: событие, кончающееся в 00:00, не попадает в следующий день.
- Неделя всегда начинается в понедельник; в URL — дата понедельника.
- Отправляем `'2026-11-20T08:00'`, принимаем и с секундами, и без.

## 5. Правила работы с API

- Один `*Api`-класс на группу эндпоинтов, методы 1:1 с эндпоинтами spec §8. **Новый вызов, которого нет в spec, не добавляется.** Нужен — это вопрос к backend, а не код во frontend.
- `*Api` не хранит состояние, не показывает ошибки, не повторяет запросы. Возвращает `Observable<Dto>`.
- Базовый путь — только из `API_BASE_URL`. Никаких `http://localhost:8080` в коде.
- Модели — 1:1 с DTO, имена полей как в JSON. Преобразования (в `TimelineEvent`, в форму) — в отдельных функциях `to…` / `from…`.
- `version` — всегда: в теле PUT и в `?version=` для DELETE. Версию берём из последнего ответа сервера.
- Ошибки ловятся там, где есть контекст: форма — показывает у поля (`applyServerErrors`), стор — переводит в `status = 'error'`, остальное — `ToastService.error()`. Сравнение — по `error.code`, **не по `status` и не по тексту**.
- Заголовки `Authorization` и `X-Requested-With` ставит только `authInterceptor`. Вручную в сервисах — нельзя.
- Новая форма ответа или новый код ошибки в backend → сначала модель и `error-messages.ts`, потом использование.

## 6. Правила для компонентов

- Standalone, `ChangeDetectionStrategy.OnPush`, `input()` / `output()` / `model()`, `inject()`; новый control flow (`@if`, `@for` с `track`).
- **Страница** (`*-page`) — получает параметры маршрута через `input()`, создаёт стор, передаёт данные вниз. **Презентационный** компонент — только `input` / `output`, без сервисов с состоянием и без HTTP.
- Компоненты доски таймлайна ничего не вычисляют: всё приходит готовым в `PanelLayout` / `EventBox`. Новое вычисление → функция в `engine` с тестом.
- Логика форм и сценариев — в `*-form.ts` и сервисах, а не в классе компонента.
- Шаблон без вызовов функций с вычислениями — используйте `computed`.
- Доступность сразу: кликабельное — `<button>` или `<a>`, у иконок-кнопок `aria-label`, у полей — метка через `tp-form-field`.
- Не создавать компонент «на будущее». Компонент в `shared/ui` появляется, когда он нужен второй раз или нужен задачей roadmap.
- Неработающих кнопок нет: элемент появляется вместе с функцией.

## 7. Формы

- Reactive Forms, типизированные (`FormGroup<{…}>`, `nonNullable`).
- Ограничения — из `shared/domain/event-constraints.ts`, числа в валидаторах не пишем.
- Клиентская валидация — для удобства; **сервер — источник истины**. Бизнес-правила backend (дубли шаблонов, занятость дня, что удалить при REPLACE, нормализация DST) во frontend не повторяются.
- Ошибки показываются после первой попытки отправки или после `blur`.
- Кнопка отправки во время запроса — `loading`, повторная отправка невозможна.

## 8. Стили

- Цвета, тени, радиусы — только через CSS-переменные из `_tokens.scss`. Цвета категорий — только из `CATEGORY_PALETTE` (через CSS-переменные на элементе).
- Стили компонента — в его `.scss`; глобальные — только в `src/styles/`.
- Брейкпоинт — mixin `narrow` (< 820 px), других без решения в decisions не добавляем.
- Анимации — `tpIn`, `tpFade`; у всех — `prefers-reduced-motion`.
- Inline `style="…"` в шаблонах — только для геометрии карточек (`top`, `height`, `left`, `width`) через `[style.*]`.

## 9. Тесты

| Что | Как |
|---|---|
| Чистые функции | `it.each` по таблицам roadmap §7.4; каждый новый граничный случай — новая строка таблицы |
| `*Api`, интерцепторы | `HttpTestingController`: метод, URL, заголовки, тело; `httpMock.verify()` в `afterEach` |
| Компоненты | `TestBed` zoneless, входы через `fixture.componentRef.setInput()`, `await fixture.whenStable()` |
| Таймеры | `vi.useFakeTimers()`; `fakeAsync` и `tick` недоступны (нет zone.js) |
| Время | всегда фиксированное через токен `CLOCK`; пояс пространства в тестах отличается от пояса машины |
| Вёрстка | только Playwright; в jsdom геометрию не проверяем |

- Тест лежит рядом с файлом: `week-store.ts` → `week-store.spec.ts`.
- Проверяем поведение и числа, а не внутреннюю реализацию. Snapshot-тестов нет.
- Исправили ошибку → сначала тест, который её воспроизводит.

| Русские подписи дат, склонения | `shared/time/format-ru.ts`, `plural.ts` |
| «Сейчас» и «сегодня» | `core/time/zone-clock.ts` |
| Раскладка событий на сетке | `shared/timeline/engine/*` |
| Серверные ошибки → поля формы | `shared/forms/server-errors.ts` |
| Визуальные константы | `src/styles/_tokens.scss` |

Перед тем как написать функцию — поиск по этим файлам. Похожий код появился второй раз — выносим в одно из этих мест (или новое, с записью в decisions).

## 12. Как поддерживать документацию

- **roadmap §5** — статус каждой задачи, сразу после её завершения.
- **roadmap §12 (журнал)** — версии, отклонения от плана, найденные проблемы, новые задачи.
- **decisions** — меняется только при смене решения: строка решения правится, а в конец документа добавляется запись «дата — FD-xx — было / стало / почему». Ответы на OQ — туда же.
- Изменили API backend → сначала `backend-spec-v2.md`, затем модели (CORE-01…03) и таблица покрытия roadmap §8.
- Новая задача → в таблицу §5 и карточку §6 с полным набором полей.
- README обновляется в QA-07 и при изменении команд запуска.

## 13. Частые ошибки

| Ошибка | Как правильно |
|---|---|
| `new Date('2026-11-20T08:00')` — браузер трактует как время **своего** пояса | `parseLocalDateTime` → локальные минуты |
| «Сегодня» по часам браузера | `ZoneClock.todayIn(workspace.timeZone)` |
| `Authorization` на `/auth/login` или `/auth/refresh` — просроченный токен даёт 401 даже на `permitAll` | интерцептор пропускает эти пути (AI-02) |
| Забыли `X-Requested-With` на `POST /auth/**` → `403 CSRF_HEADER_MISSING` | ставится интерцептором на все запросы |
| После refresh повторяем запрос со старым токеном | повтор берёт токен из результата refresh |
| Новые строки шаблона после сохранения остаются с `id: null` → при следующем PUT дубли | форма пересобирается из ответа T2/T4 |
| `confirmedDeleteIds` берутся из нового запроса предпросмотра, а не из показанного | только из объекта на экране (AP-07) |
| Две прокрутки панелей, синхронизированные через `scroll`-события | один scroll-контейнер (FD-57) |
| Таймлайн как `<table>` или сетка ячеек по 30 минут | абсолютное позиционирование по минутам |
| Событие, которое кончается в 00:00, появляется в следующем дне | полуоткрытый интервал (TL-05) |
| Локальное удаление события из массива после DELETE | `eventsChanged()` → перезагрузка |
| `fakeAsync` в тесте | `vi.useFakeTimers()` |
